# cozmo_clone — 設計の前提

Anki Cozmo（2016）のクローン。段階 1（ヒアリング）の結果。

## 目的

卓上で動く小型キャラクターロボット。キャタピラで走行し、リフトアームでキューブを操作し、
ヘッドチルトと顔ディスプレイで表情を作る。映像は母艦（PC / スマホ）へ WiFi で飛ばし、
顔認識・マーカー認識は母艦側で行う。

使用環境: **屋内・卓上。可搬（手で持ち運ぶ）。防水・防塵は不要。**

## ヒアリングで確定した事項

| 項目 | 決定 |
|---|---|
| 再現範囲 | **フル再現・4自由度**（左右走行 + リフトアーム + ヘッドチルト + 顔ディスプレイ） |
| 外形サイズ | **実物の約 1.5 倍、全長 約 150 mm** |
| 駆動方式 | **キャタピラ（無限軌道）** |
| 制御系 | **M5Stack 系で統一** |
| 画像処理 | **母艦（PC / スマホ）に飛ばす**。ロボット側は映像送信とモータ制御に専念 |

実物大 100 mm を選ばなかった理由: 4自由度ぶんの駆動系（DC モータ 2 + サーボ 2）と電源を
市販部品で 100 mm に収めるのは成立しにくい。1.5 倍にすることで見た目の雰囲気を保ちつつ
設計を成立させる。

## 構成（提案・段階 2 で確定させる）

```
[母艦 PC/スマホ] ←WiFi(MJPEG)── [Unit CamS3: 映像配信専用(独立)]
       └──WiFi(操縦/認識結果 UDP)──→ [AtomS3R]
                                        │ ESP32-S3 + BMI270 IMU
                                        │ I2C(Grove) ─┬─ [Atomic Motion Base v1.2]
                                        │             │     ├ DC ch1/ch2: 走行モータ L/R
                                        │             │     └ SERVO ch1/ch2: リフト / ヘッドチルト
                                        │             └─ [Unit OLED 1.3": 顔]
                                        └ 電源: 18350 Li-ion(Motion Base 内蔵ホルダ)
```

### 部位の割り当て

| 部位 | 搭載物 | 意図 |
|---|---|---|
| 頭（チルトする） | Unit OLED（顔）、Unit CamS3（カメラ） | Grove 4 線だけが首を通る。重量物を頭に置かない |
| 胴体 | AtomS3R + Atomic Motion Base（純正スタック）、18350 電池 | 重心を低く、後方寄りに |
| 胴体下部 | 走行モータ ×2、キャタピラ | |
| 胴体前方 | リフトアームサーボ ×1、平行リンク | Cozmo 同様、アームは前方へ張り出す |

### 部品選定の根拠

- **顔 = M5Stack Unit OLED 1.3"（128×64 モノクロ）**
  実物 Cozmo の顔も 128×64 のモノクロ OLED。解像度・表現ともに最も忠実な選択肢になる。
  Grove の I2C 4 線だけで駆動でき、チルト関節を通す配線が最小になる。
- **制御 = AtomS3R + Atomic Motion Base v1.2**
  Motion Base 単体で「DC 2ch + サーボ 4ch + 18350 電池ホルダ + 電流監視」が揃い、
  本機の 4 自由度にちょうど一致する。AtomS3R と 24×24 mm で純正スタックできるため、
  胴体内は 1 つのブロックとして扱える。AtomS3R 内蔵の BMI270 で持ち上げ検知・転倒検知ができる。
- **カメラ = Unit CamS3**
  ESP32-S3 内蔵の独立した WiFi カメラ。制御系と分離するため、映像送信が制御ループを妨げない
  （pen_robo の M5Camera と同じ考え方）。

### 検討したが採らなかった案

- **AtomS3R を頭に置き、顔として使う**: 0.85 インチ 128×128 の LCD で顔を作れるが、
  制御中枢が首の先に来るため、チルト関節を通る配線がモータ電源を含めて太くなる。
  また画面が正方形で Cozmo の横長の顔と合わない。
- **実物大 100 mm**: 上記のとおり部品が収まらないリスクが高い。

## 外部インターフェース

- **USB-C ×2**: AtomS3R（書き込み・充電）、Unit CamS3（書き込み）。**ケースを開けずに届くこと**
- **電源スイッチ**: 胴体側面または底面
- **カメラ窓**: 頭部前面。Cozmo 同様レンズを「目」の位置ではなく額〜口元に置く
- **顔ディスプレイ窓**: 頭部前面。OLED のガラス面を露出させるか、透明窓を被せる

## 未確定事項（段階 2・3 で詰める）

1. **Atomic Motion Base を AtomS3R から分離して I2C 制御できるか**
   本設計は純正スタック（胴体内で重ねる）前提のため影響は小さいが、レイアウト変更時に効く
2. **キャタピラの調達方法**: タミヤ 70100 トラック&ホイールセットの流用か、TPU での自作か。
   スプロケット径・トラック幅・リンクピッチが未確認のため、走行部の骨格寸法が決まらない
3. **走行モータの型番**: N20 系ギヤードモータを想定。ギヤ比・エンコーダ有無が未決定
4. **リフトアームのリンク寸法**: Cozmo は平行リンクでフォークを水平に保つ。リンク長は
   キューブ寸法（自作する場合は任意）と持ち上げ高さから決める

## この機体のリスク

- **卓上運用＝落下**: Cozmo は 4 個の崖センサで机の端を検知する。これが無いと初回で落ちる。
  崖センサは「あったら良い」ではなく必須部品として BOM に入れる
- **首を通る配線**: チルト可動域ぶんのたるみ（サービスループ）を確保しないと断線する。
  配線が占める体積を BOM の `wiring` に体積付きで計上する
- **重心**: キャタピラ車は重心が高いと登坂・段差でひっくり返る。電池を最下部・後方に置く
- **リフトアームの保持力**: マイクロサーボは無負荷時も脱力しない。持ち上げ状態を保つと
  発熱・消費電流が続く。ウォームギヤかラッチ機構でセルフロックさせるかを段階 4 で判断する
